## Data export

ADR 0051 records these decisions (the maintainer's on #39). The export holds a player's decrypted personal data, so it is privacy-sensitive.

- `POST /api/v1/me/export` (`request_data_export`) needs a recent reauthentication (`config.auth.require_recent_reauthentication`, 403 `reauthentication_required`, nothing written). Its only throttle is `DataExportThrottle` (`apps/exports/api.py`): a request with a recent reauthentication (`config.auth.recently_reauthenticated`) counts against a day window from `API_DATA_EXPORT_THROTTLE_PER_DAY`, and one without counts against the Account throttle's windows instead, so a refusal never spends an export request. It answers 202 with `requested_at`, and 404 when the Account was deleted meanwhile. A new request deletes an earlier export, so a link already mailed for it then gets the 404.
- Change a `DataExport` only through `apps.exports.services`. `request_export(account)` locks the Account `FOR NO KEY UPDATE` (refusing an inactive one), deletes any earlier export (built or not), stores a pending row, records one `data_export.request` event (actor and target the Account, no values), and queues `build_data_export` with the row id after commit.
- `build_data_export(export_id)` holds the Account `FOR KEY SHARE` (`hold_active_account`), then locks the row `FOR UPDATE`, and builds only a pending row: the JSON in `content` (`EncryptedTextField`), the SHA-256 of a new `secrets.token_urlsafe(32)` key in `key_hash`, `built_at`, and `expires_at` (`LINK_LIFETIME`, 24 hours), and one email to `User.email` with `{FRONTEND_URL}/account/export/{key}`, in one transaction. A rerun, a missing row, and an inactive Account write nothing. A build that fails stays pending: the sweep queues it again hourly, and deletes it 24 hours after the request, with no email. The key is never stored, logged, put in a task argument, or recorded in an Audit Event.
- `POST /api/v1/me/export/download` (`download_data_export`) takes `{"key": ...}` behind sign-in and the Account throttle, with no reauthentication. `download_export()` holds the Account `FOR KEY SHARE` first (`hold_active_account`, the lock order of the build and Account deletion), then finds a ready, unexpired row of that Account by the key's hash `FOR UPDATE`, records one `data_export.download` event (no values), deletes the row, and returns the JSON as an attachment with `Cache-Control: no-store`. An empty key, one over `KEY_MAX_LENGTH` (128), one that is not ASCII (a lone surrogate included), an inactive Account, and an unknown, used, expired, unbuilt, or other Account's key get one fixed 404 (the length limit is the service's, so a long key is a 404, not a 422).
- The builder (`apps.exports.builder.build_export`) only reads. Decrypted values are the Account's own Player's only. Other players appear only through `match_out(match, viewer=account)` (loaded with `with_match_details`). Audit Events: those targeting the Account, its Player, its privacy row, its rating states, or its agreement rows, plus those the Account made, each with action, time, target type, target OPEN Code, and the actor as `you`, `staff`, `other`, or `system`; `before` and `after` only for those own records, with row id keys removed (`ROW_ID_VALUE_KEYS` and `*_id`); never `reason`. Never read a session key, a session's or MFA method's `data`, a client secret, an approver, a token, or a code into it, and never a results file's content or report, a match's `rating_format`, a vouch's flag, or an Organizer Report's close reason or closer. Sections that add own fields to a public schema subclass it (`ExportMatchOut`, `ExportRatingOut`, `ExportRatingHistoryItemOut`), so the public responses do not change; Organizer memberships keep the `OrganizerMembershipOut` shape (ADR 0050). Removed rating states are found through the `player` key of their `rating.change` events. ADR 0051 lists every deliberate omission.
- The format is `DataExportOut` (`apps/exports/schemas.py`) with `format_version` `"1"`, documented in `docs/data-export.md`. Change the schema, the doc, and the OpenAPI document together; a change that breaks readers bumps `format_version`.
- `apps/exports/tests/test_coverage.py` lists every model with a foreign key or one-to-one link to the Account model or `players.Player` as exported or excluded with a reason. A new link fails it until the issue that adds it decides.
- `sweep_data_exports` (beat `sweep-data-exports`, every 15 minutes, default queue) deletes rows past `expires_at`, pending rows requested more than `LINK_LIFETIME` ago, and queues again pending rows last queued more than `REQUEUE_AFTER` (one hour) ago. The build task's time limit stays under it and the broker's visibility timeout.
- No admin is registered for `DataExport`, and `__str__` shows only the row id.
