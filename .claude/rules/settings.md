## Settings

- `config/settings.py` reads its deployment values from the environment (and an optional `.env`). Read a new variable with the helpers there (`_raw`, `_required`, `_list`), not django-environ's `Env` getters: those treat a value starting with `$` as a reference to another variable, which silently swaps secrets and URLs.
- The errors that `config/settings.py` raises for a bad or missing variable name the variable and never echo its value. django-environ's own `.env` reader is the exception: it logs a malformed `.env` line in full.
- With DEBUG off, settings turn on the https redirect, secure cookies, and HSTS (see ADR 0004). The one exception is `HealthProbeMiddleware` (`config/health_probe.py`, ADR 0042), right after the three header middlewares in `MIDDLEWARE` and ahead of `SecurityMiddleware`: it answers a GET of exactly `/api/v1/health/live` or `/api/v1/health/ready` itself when the host is not allowed or the request is plain http with the redirect on, because App Platform probes the container that way. Keep its match exact, and never widen it to another path or method. The test run applies a fixed set of overrides (the list is `_TEST_OVERRIDES` in `config/test_runner.py`), so tests run over plain http, run Celery tasks eagerly with errors propagated, hash passwords with fast MD5 (the production hashers stay listed after it), and need no cache server, no broker, no `collectstatic`, and no network (the breached password check's URL points at a local port nothing listens on). pytest gets these overrides from `config/settings_test.py`, and `manage.py test` gets them from `config/test_runner.py`. Keep the two sets identical (a test fails if they drift). pytest's set lives in the settings module, so every process that loads it, parallel workers included, gets it; the runner applies its set in spawned parallel workers through `process_setup` (forked workers inherit it).
- `DATABASE_URL` may point at a PgBouncer pool in transaction mode (a DigitalOcean connection pool), with `DIRECT_DATABASE_URL` naming the database itself (ADR 0038). A non-blank `DIRECT_DATABASE_URL` turns on pooled mode: `default` (the pool) gets `CONN_MAX_AGE` 0 and `DISABLE_SERVER_SIDE_CURSORS`, settings refuse `prepare_threshold`, `assume_role`, and `pool` in its query (naming the variable and option, never the value), and a `direct` alias is added, mirrored to `default` in tests. Empty, there is only `default`, as before. OPEN's `migrate` (`apps/database`), run as `manage.py migrate` from the command line (the deploy job) in pooled mode with no `--database` given, points the `default` connection at the direct database for its own process (keeping default's `TEST` settings) and migrates `default`, so every migration and `post_migrate` handler runs direct with no edits; an in-process `call_command("migrate")` and an explicit `--database` are honored as given and rebind nothing (parallel test workers do not mirror `direct`, and the rebind is never undone). Because each transaction may get another server connection, never keep session state: use only transaction-level advisory locks (`pg_advisory_xact_lock`), and no `SET` or `SET SESSION` (`SET LOCAL` is fine), `LISTEN`, temporary tables, `WITH HOLD` or other named cursors, or prepared statements. As good practice, a new `RunPython` function queries through `schema_editor.connection.alias`, but nothing depends on it; never edit a merged migration for this.
- `REDIS_URL` takes only the form `redis://[USER:PASSWORD@]HOST[:PORT][/DB]`, or `rediss://` for TLS: a lowercase scheme, a numeric database, and no query string or fragment. Settings refuse at startup a URL that breaks these rules. redis-py lets a query string override settings, certificate verification included, so set connection and TLS options in settings, never in the URL. Percent-encode any URL-reserved character in the password.
- Celery's broker is `REDIS_URL`, the same Valkey database as the cache, so clearing the cache (`RedisCache.clear()` runs FLUSHDB) also drops queued tasks. Settings refuse to start when `CELERY_BROKER_URL`, `CELERY_BROKER_READ_URL`, `CELERY_BROKER_WRITE_URL`, or `CELERY_RESULT_BACKEND` is set to a non-empty value in the environment (or `.env`): Celery would read it ahead of settings and skip the `REDIS_URL` checks. Set broker and TLS options in settings.
- Celery has four queues: `default`, `ratings`, `email`, and `webhooks` (ADR 0006). `CELERY_TASK_ROUTES` routes a task by the start of its name: tasks in `apps.ratings.tasks`, `apps.emails.tasks`, and `apps.webhooks.tasks` go to the matching queue, and every other task goes to `default`. A task given an explicit name outside its module's pattern goes to `default`. Sending to a queue that is not declared raises `QueueNotFound`. A new queue needs a declaration, a route, and the `-Q` list of every worker command (compose, the README's local and production image commands, deploy).
- Tasks are acknowledged late, so a crash redelivers them: every task must be safe to run twice. Keep each task's time limit, and any countdown or ETA, below the broker's one-hour visibility timeout, or the task runs twice. Pass ids, not model instances, and keep secrets and personal data out of task arguments and return values (the worker logs return values).
- Static files use WhiteNoise's compressed manifest storage. With DEBUG off, every page that uses `{% static %}` (the admin, `/api/v1/docs`, `/_allauth/openapi.html`) returns a 500 until `collectstatic` has run, `runserver` and the compose `web` profile included. WhiteNoise sends no CORS header on static files.
- CORS covers `/api/` and `/_allauth/` paths only, for the exact origins in `CORS_ALLOWED_ORIGINS` (empty by default, so no origin is allowed). `CORS_ALLOW_HEADERS` is corsheaders' defaults plus the three headers allauth reads (`X-Session-Token`, `X-Email-Verification-Key`, `X-Password-Reset-Key`) and the app client's `X-Device-Token` (ADR 0047), so allauth's app client works cross-origin. `CORS_EXPOSE_HEADERS` lists `Retry-After`, so a cross-origin client can read a throttle's wait, and `X-Device-Token`, so the app client can read the device token a login returns. The browser client uses the session cookie, so it works same-origin only (served from or proxied through the API host); ADR 0040 keeps credentials off. Settings refuse at startup an entry that is not exactly `scheme://host[:port]`: no wildcard, path, trailing slash, or default port. `CORS_ALLOW_CREDENTIALS` and `CORS_ALLOW_ALL_ORIGINS` stay False, and `CORS_ALLOW_ALL_ORIGINS` is never read from the environment.
- Security headers and cookies (ADR 0040). With DEBUG off, the session and CSRF cookies are `__Host-sessionid` and `__Host-csrftoken` (Secure, path `/`, no `Domain`, `SameSite=Lax`, the session cookie HttpOnly, the CSRF cookie readable because the browser client reads it); with DEBUG on, `sessionid` and `csrftoken`. Every response gets `X-Content-Type-Options`, `Referrer-Policy: strict-origin-when-cross-origin`, `Cross-Origin-Opener-Policy: same-origin`, `X-Frame-Options: DENY`, a `Permissions-Policy` that turns off unused features (`config/security_headers.py`, which leaves out passkeys and fullscreen), and the Content Security Policy (same-origin scripts, styles, fonts, and requests, `data:` images, no inline script or style, no eval, `frame-ancestors 'none'`). The CSP, Permissions-Policy, and X-Frame-Options middlewares come first in `MIDDLEWARE`, so early responses (the 413, CORS preflights, static files, the https redirect) carry them, and the body limit comes right after `CorsMiddleware`. Never add `'unsafe-inline'`, `'unsafe-eval'`, or another host to the policy; a page that needs an exception uses django-csp's per-view decorators (the embed, #96, adds its framing exception that way). Every page loads its scripts and styles from the static files, with no inline script: allauth's OpenAPI page uses OPEN's template with django-ninja's bundled Swagger UI. `CSP_REPORT_ONLY` (read into a private name) picks the mode: true sends only the report-only header, false only the enforced one, unset or empty means report-only with DEBUG on and enforced with DEBUG off, and any other value stops startup (`_flag()` accepts true, yes, on, 1, false, no, off, 0). With no report endpoint, report-only violations reach only the browser console.
- `CSRF_TRUSTED_ORIGINS` is checked like `CORS_ALLOWED_ORIGINS` (exact origins, the error names the variable and never echoes the value), and with DEBUG off every entry must be https. Empty by default; real hosts come from the environment.
- CI's `test` job runs `manage.py check --deploy --fail-level WARNING` with made-up production-like values, and a test keeps those values passing. `SILENCED_SYSTEM_CHECKS` is empty: any entry needs a comment saying why.
- gunicorn reads `PORT` and `WEB_CONCURRENCY` from the process environment only, never from `.env`. gunicorn parses `WEB_CONCURRENCY` itself before `gunicorn.conf.py` runs, so its own error reports a non-integer value. The config turns off gunicorn's control socket.
- `API_ACCOUNT_THROTTLE_PER_MINUTE` (default 120), `API_ACCOUNT_THROTTLE_PER_DAY` (10000), `API_CLIENT_IP_THROTTLE_PER_MINUTE` (60), and `API_CLIENT_IP_THROTTLE_PER_DAY` (3000) are the API throttle rates (ADR 0030), each a whole number from 1 to 1000000, read on each request. `CLIENT_IP_HEADER` (default `do-connecting-ip`) names the header the proxy sets to the client IP: letters, digits, and hyphens, lowercased. Settings refuse `X-Forwarded-For` and `Forwarded`, which a client can forge, and `Content-Type` and `Content-Length`, which never reach Django as `HTTP_` headers.
- `API_ORGANIZER_REPORT_THROTTLE_PER_DAY` (default 5, a whole number from 1 to 1000000, read on each request) is the day limit on Organizer Reports per Account (ADR 0037). `API_DATA_EXPORT_THROTTLE_PER_DAY` (default 3, a whole number from 1 to 1000000, read on each request) is the day limit on data export requests per Account (ADR 0051). `ORGANIZER_REVIEW_WINDOW_DAYS` (default 90, 1 to 36500) is how many days back the Organizer admin's moderator review counts disputes and signal flags.
- `UNUSUAL_SUBMISSION_FIRST_MATCHES` (default 25), `UNUSUAL_SUBMISSION_BATCH_SIZE` (100), `UNUSUAL_SUBMISSION_DAILY_MATCHES` (200), and `UNUSUAL_SUBMISSION_PLAYER_DAILY_MATCHES` (30, ADR 0052) are the unusual submission thresholds (ADR 0049): each a whole number from 1 to 1000000, read with `_version()`, unset or empty giving the default. A bad value stops startup, naming the variable without its value.
- `MATCH_CONFIRMATION_EXPIRY_DAYS` (1 to 36500, empty by default) makes the daily expiry task `expire_unconfirmed_matches` void pending matches submitted (`created_at`) more than that many days ago (ADR 0013). The task is always scheduled; empty, it does nothing. The task's schedule is `CELERY_BEAT_SCHEDULE` in settings, which the database scheduler copies over the stored row at each beat start, so change a schedule there, not in the admin.
- `MATCH_DISPUTE_EXPIRY_DAYS` (default 30) and `MATCH_DUPLICATE_HOLD_DAYS` (default 14) are the dispute and possible duplicate hold periods of the daily `expire_disputes_and_holds` task (ADR 0034; the hold period voids the newer Match only when the earlier one is confirmed): each a whole number from 1 to 36500, read with `_days()`. Unset or empty gives the default; no value turns either off. A bad value stops startup, naming the variable without its value.
- Account security (ADR 0047), each read on startup, a bad value naming the variable and never echoing it: `PASSWORD_MIN_LENGTH` (default 8, 8 to 128), `PASSWORD_BREACH_TIMEOUT_SECONDS` (default 3, 1 to 10), `SESSION_MAX_AGE_DAYS` (default 30) and `SESSION_IDLE_DAYS` (default 7, at most the lifetime), and `SIGN_IN_DEVICE_COOKIE_DAYS` (default 365). `SESSION_COOKIE_AGE` stays at Django's 14 days, for signed-out sessions (signed-in ones set their own expiry). The rate limits (`ACCOUNT_RATE_LIMITS`), `SESSION_SEEN_REFRESH_SECONDS`, `SIGN_IN_DEVICE_MAX_TAGS`, and `PASSWORD_BREACH_API_URL` are set in settings, never the environment: the breach URL must not be changeable by a deployment setting, since it receives hash prefixes. No account limit or lifetime is hard-coded outside settings.
- `ADMIN_URL` is the admin's path (ADR 0045), read with `_admin_url()`: path segments of ASCII letters, digits, `-`, and `_`, each ending in `/`, no leading slash, at most 100 characters, and a first segment other than `api`, `_allauth`, `oauth`, or `static`. With DEBUG on, unset or empty gives `admin/`; with DEBUG off it is required and `admin/` is refused in any letter case. The reserved first segments are compared without regard to case too. Production sets it in the App Platform console. The test overrides pin it to `admin/`, so tests may use `/admin/` whatever valid path `.env` sets. `ADMIN_SESSION_SECONDS` (default 3600, at least 30) is how long after its latest MFA step a staff session opens the admin, and `ADMIN_REAUTHENTICATION_SECONDS` (default 300 or the session limit if lower, at least 30, at most the session limit) how recent that step must be for a write; both are whole seconds, at most 86400, read with `_seconds()`.
- `FIELD_ENCRYPTION_KEYS` (ADR 0046) is a comma-separated list of Fernet keys (urlsafe base64 of 32 bytes), newest first, read with `_encryption_keys()`: the newest encrypts and every listed key decrypts. With DEBUG off it is required; with DEBUG on it may be empty, and then reading or writing an encrypted field raises `ImproperlyConfigured` with fixed text. A malformed entry stops startup in any mode, naming the variable and the entry's position, never a value. Never commit a key, a test key or a CI key included: the test overrides generate one per process at import (`config/test_runner.py`, read by `config/settings_test.py`), settings tests generate theirs, and the CI deploy check generates one in its step. Rotate by putting a new key first, running `reencrypt_fields`, then removing the old key; losing every key loses the encrypted data. Production sets it in the App Platform console. The data migrations that encrypt existing rows need it only when rows exist.
- `FRONTEND_URL` is required: the web app's exact origin, checked like a CORS entry, and https when DEBUG is off. allauth's email links (verify an address, reset a password) open pages under it (`HEADLESS_FRONTEND_URLS`), and so do the match confirmation request's and the match notices' links (`match_url()`).
- `OPEN_PUBLIC_PROFILE_URL` is optional, default `https://openpb.org/players/`: the rating lookup's `profile_url` is it followed by the OPEN Code. Settings refuse a value that is not an absolute http or https URL whose path ends in `/`, or that has a query, fragment, or user info, and require https when DEBUG is off.
- `EMAIL_BACKEND` is a Django email backend path from the environment, passed through as is. With DEBUG on and no value, email prints to the console (of the Celery worker, since a task sends it). With DEBUG off it is required, and backends that print or keep messages are refused (the list is in `config/settings.py`). With Resend's backend (`anymail.backends.resend.EmailBackend`) and DEBUG off, `RESEND_API_KEY` is required (read into `ANYMAIL`). `DEFAULT_FROM_EMAIL` is required with DEBUG off, and `SERVER_EMAIL` follows it. Switching to Amazon SES needs no code change: `uv add "django-anymail[amazon-ses]"`, then set `EMAIL_BACKEND` and boto3's AWS variables (boto3 timeouts are optional tuning, see the Email section). Never let a DEBUG-off environment print or log email: messages carry recipient addresses and verification and reset keys.
