# Personal data inventory

This file lists every field in which OPEN stores personal data. It is the source for the privacy policy. [ADR 0009](../adr/0009-personal-data.md) sets the rules.

Personal data means data about an identifiable person, including any data linked to a Player or an Account.

A pull request that adds, changes, or removes a personal data field updates this file in the same pull request. A test (`config/tests/test_personal_data_inventory.py`) fails when an installed model is not named here by its label, or when a field of a first-party model is not named under its model.

A reason is stored only from a moderator, from the Event's verified Organizer settling a dispute (`dispute.outcome` and `match.edit`, ADR 0034; a member or the submitting Partner Application), or from an organizer verifier for `organizer.verify`, `organizer.unverify`, and `organizer_report.close`; a player's dispute stores none. A Player profile change (`player.profile_change`) records only the changed field names. A staff reveal of a Player's personal data in the admin (`player.personal_data_view`, ADR 0046) records the staff Account as actor, the Player as target, and only the names of the fields shown (`birth_month`, `birth_year`, `gender_division`, `legal_name`), never a value. An Event create, change, or delete (`event.create`, `event.change`, `event.delete`, ADR 0035) records the Event's `name`, `kind`, dates, and the Organizer's and Club's OPEN Codes (a change records only the changed fields, old and new); none is an identifying field. An MFA change (`mfa.change`, ADR 0043) records only the change (`added`, `removed`, `regenerated`, `used`) and the authenticator type, never a secret or a code. An admin change (`admin.add`, `admin.change`, `admin.delete`, ADR 0045) records the staff Account as actor (none when the delete removes that Account) and the object as target; `admin.change` names every changed field, and values are recorded only for the fields listed per model (an Account's `is_active`, `is_staff`, `is_superuser`, and the row ids of its groups and user permissions; a Group's name and permission row ids). An admin action (`admin.action`) records the action's name for each selected object. ### Not personal data

These were checked and hold no personal data on their own:

- `public_ids.IssuedCode` (`code`, `issued_at`): the registry of issued OPEN Codes. It has no link to the record (ADR 0008).
- `ratings.RatingReplay` (`created_at`, `as_of`, `config_version`, `config_fingerprint`, `params_version`, `parameter_fingerprint`, `matches_considered`, `matches_counted`, `net_rating_created`, `engine_version`, `spec_version`): one replay's provenance (as-of date, config and engine versions, fingerprints, match counts, net rating created per format). It names no Player (ADR 0025).
- `ratings.RatingReplayRequest` (`created_at`, `earliest_date`, `reason`): a pending request for a replay (an earliest match date, a reason, and when it was made), deleted by the replay that takes it. It names no Player (ADR 0028).
- django-celery-beat's tables (`django_celery_beat.PeriodicTask`, `django_celery_beat.PeriodicTasks`, and the schedule tables `django_celery_beat.IntervalSchedule`, `django_celery_beat.CrontabSchedule`, `django_celery_beat.SolarSchedule`, `django_celery_beat.ClockedSchedule`): periodic task definitions. Task arguments must never carry personal data (`CLAUDE.md`, Settings).
- `clubs.Club` (`name`, `city`, `region`, `public_code`): a Club is a place or group, not a person. Any signed-in Account reads a Club's code, name, city, and region (`get_club`, #230); its admins set them, and may not rename a Club once an Event or Match names it. `club.change` Audit Events name the changed fields only, never the values (#230).
- Django's `auth.Permission`, `auth.Group` (`name`), and `contenttypes.ContentType`.
